# خطة تجهيز محرر للمنح والقبول المفتوح المصدر

## الهدف

هذه الخطة تحول مشروع **محرر / Muharrir** من مشروع خاص جيد تقنيا إلى مشروع مفتوح المصدر قابل للتقديم على برامج دعم ومنح أدوات المطورين والذكاء الاصطناعي.

الهدف ليس فقط جعل المستودع عاما. الهدف هو جعله مقنعا لجهات مثل برامج OSS grants أو أدوات المطورين، بحيث يظهر بوضوح أنه:

- مشروع مفتوح المصدر حقيقي.
- يخدم مطورين وصناع محتوى ومستخدمين عربا وإنجليزا.
- قابل للتثبيت والاستخدام مباشرة.
- له حوكمة ومساهمة واختبارات وإصدارات.
- له زاوية مميزة عن أدوات Prompt العادية.

## الحكم الاستراتيجي

بعد مقارنة محرر مع RepoPulse وMECA:

1. **Muharrir هو أفضل مرشح للقبول بعد التجهيز** لأنه منتج واضح ومفيد ومميز عربيا.
2. **RepoPulse أسهل كـ OSS لكنه أضعف كقصة قبول** لأنه في مساحة مزدحمة ولم يحصل على قبول سابق.
3. **MECA أعمق من ناحية الأثر التعليمي لكنه يحتاج إعادة تموضع كبيرة** قبل أن يصلح كمنحة مفتوحة المصدر.

لذلك تكون الأولوية:

1. تجهيز Muharrir كمنتج OSS قوي.
2. إبقاء RepoPulse نشطا بتطوير محدود.
3. تأجيل MECA أو استخراج نسخة عامة منه لاحقا.

## موقع محرر الحالي

نقاط قوة المشروع:

- تطبيق Next.js + TypeScript.
- دعم عربي وإنجليزي مع RTL.
- Local-first: بيانات المستخدم محلية.
- يعمل Web وDesktop عبر Tauri.
- يدعم مزودين متوافقين مع OpenAI.
- يدعم تحليل PDF وDOCX والصور.
- عنده فكرة عملية: تحويل الأفكار الغامضة إلى Prompt منظم عبر حوار تفاعلي.
- عنده أساس تقني جيد: Zustand, Dexie, Tauri, Keychain, Playwright, Vitest.

المشاكل قبل التقديم:

- المستودع خاص حاليا.
- ملف LICENSE يقول Proprietary بينما README يقول MIT.
- `package.json` يحتوي `private: true` واسم package عام `app`.
- لا توجد ملفات OSS كافية: CONTRIBUTING, SECURITY, CODE_OF_CONDUCT, ROADMAP.
- لا توجد صفحة Demo أو Screenshots كافية في README.
- لا توجد إصدارات Releases واضحة.
- لا توجد Issues مهيأة للمساهمين الجدد.
- يجب توضيح الخصوصية وحدود استخدام مفاتيح API.

## التموضع المقترح

لا نسوقه كـ chat app عام. هذا سيجعله عاديا.

التموضع الصحيح:

> Muharrir is a local-first Arabic/English prompt engineering workspace that helps users turn vague ideas, documents, and requirements into structured, reusable AI prompts through guided multi-step refinement.

بالعربية:

> محرر مساحة عمل محلية أولا بالعربية والإنجليزية لتحويل الأفكار والمستندات والمتطلبات الغامضة إلى موجهات ذكاء اصطناعي منظمة وقابلة لإعادة الاستخدام عبر تحسين تفاعلي متعدد الجولات.

## الجمهور المستهدف

- المطورون الذين يريدون بناء Prompts دقيقة للأدوات والـ agents.
- صناع المحتوى التقني الذين يكتبون تعليمات طويلة للنماذج.
- المعلمون والمدربون الذين يحولون أهداف الدرس إلى تعليمات AI.
- فرق المنتجات التي تريد تحويل أفكار مبهمة إلى مواصفات أو مهام.
- المستخدمون العرب الذين يحتاجون أداة prompt engineering محترمة RTL/Arabic-first.

## الزاوية المميزة

يجب أن نثبت أن محرر ليس مجرد واجهة دردشة. الزاوية:

1. **Arabic-first Prompt Workspace**: دعم عربي حقيقي وليس ترجمة سطحية.
2. **Local-first Privacy**: المحادثات والإعدادات محلية، ومفتاح API في Tauri محفوظ في OS Keychain.
3. **Document-to-Prompt**: تحويل PDF/DOCX/images إلى سياق قابل لتوليد prompts.
4. **Prompt Iteration Workflow**: أدوات ask_questions, suggest_enhancements, propose_prompt.
5. **Web + Desktop**: نفس الكود يعمل كتطبيق ويب وسطح مكتب.
6. **Multi-provider**: OpenAI-compatible providers, DeepSeek, Qwen, GLM, وغيرها.

## معايير النجاح قبل التقديم

لا تقدم للمنحة قبل تحقق هذه النقاط:

- المستودع Public.
- الرخصة واضحة ومفتوحة: MIT أو Apache-2.0.
- README حديث ومقنع بالإنجليزية والعربية.
- صور أو GIF أو فيديو قصير يشرح الاستخدام.
- Release أول واضح: `v0.3.0` أو `v1.0.0-beta.1`.
- GitHub Actions تمر بنجاح: lint, typecheck, unit tests, build.
- Issues جاهزة للمساهمين.
- Roadmap واضح.
- ملف Security يشرح الخصوصية ومفاتيح API.
- ملف Contributing واضح.
- Demo أو طريقة تجربة بدون مفتاح عبر demo mode.

## ملاحظة مهمة

لا تجعل الهدف فقط "الحصول على منحة". اجعل المشروع يستحق المنحة حتى لو لم تقبل أول مرة. برامج المنح غالبا لا تكافئ الفكرة وحدها، بل تبحث عن نضج، استخدام، مساهمات، وضوح، وفائدة للمنظومة.
