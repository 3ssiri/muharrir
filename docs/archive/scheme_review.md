# مُكرِّر المطالبات التفاعلي - الخطة المُعدَّلة والتفاصيل التقنية

## 1. تأكيد تغييرات المتطلبات الأساسية
- **مجال التركيز**: التركيز فقط على تطبيق ويب لتحسين المطالبات التفاعلي (لا علاقة له بكتابة الأبحاث).
- **بنية النشر**: تطبيق واجهة أمامية بحتة (Serverless/Vercel)، **بدون قاعدة بيانات خلفية**.
- **خصوصية البيانات**: جميع البيانات الحساسة (مفتاح LLM API، سجل المحادثة، الإعدادات) يجب أن **تُخزَّن بشكل دائم في متصفح المستخدم**.
- **قيود التفاعل**: دعم **النص الخالص** فقط في التفاعل (تعطيل الصوت).
- **التجربة الأولية**: لا يجب أن تكون الصفحة الرئيسية فارغة، بل يجب أن تتضمن تلميحات إرشادية (Hints/Starters).

## 2. تفصيل خطة التحسين

### 2.1 استراتيجية التحسين متعددة الأبعاد (Multi-dimensional Optimization)
لا ينبغي للنظام أن يسأل فقط "ماذا تريد أن تكتب"، بل يجب أن يُولِّد خيارات مُسبقة (Checkbox) بشكل استباقي بناءً على الأبعاد التالية:
1.  **البُعد الهيكلي**: تقرير Markdown، مخطّط نص خالص، بيانات JSON، كتلة كود.
2.  **بُعد الدور/النبرة**: دقّة أكاديمية، سهولة الفهم العام، إبداع متشعّب، خبير تقني.
3.  **بُعد سلسلة التفكير (CoT)**: هل يجب أن يُظهر الذكاء الاصطناعي عملية الاستدلال، وهل يجب التأمل الذاتي.
4.  **القيود**: حدّ عدد الكلمات، النمط اللغوي (عربي/إنجليزي)، مجموعة مصطلحات محددة.

### 2.2 اختيار تقنية التخزين الدائم على جانب المتصفح (Client-side Persistence)
نظرًا لعدم وجود قاعدة بيانات خلفية، سنعتمد بنية "المحلية أولًا (Local-First)":

| نوع البيانات | الحل الموصى به | تفاصيل التنفيذ التقني |
| :--- | :--- | :--- |
| **إعدادات LLM** (API Keys, Models) | **LocalStorage** + التشفير | استخدام `zustand` + الوسيط `persist`. يُنصح بإجراء تعتيم خفيف على مفتاح API قبل تخزينه لمنع قراءته كنص صريح مباشرةً عبر XSS. |
| **سجل المحادثة** (Chat History) | **IndexedDB** | LocalStorage محدود بـ 5MB، وسجل المحادثة قد يتجاوز ذلك بسهولة. يُنصح باستخدام **Dexie.js** لتغليف IndexedDB، فهو يدعم تخزين كميات ضخمة من النصوص. |
| **تفضيلات المستخدم** (Theme, Presets) | **LocalStorage** | أزواج مفتاح-قيمة بسيطة، تُخزَّن مباشرةً. |

### 2.3 تصميم الإرشاد الأولي (Landing Experience)
عند تحميل الصفحة الرئيسية، لا تُعرض ChatInput فارغة، بل تُعرض **"Inspiration Cards" (بطاقات الإلهام)**:
- "تحسين مطالبة لمخطّط بحث أكاديمي"
- "تصميم مساعد لمراجعة كود Python"
- "إنشاء أمر رسم لـ Midjourney"
*بعد أن ينقر المستخدم على البطاقة، يُملأ Input Box تلقائيًا، ويُشغَّل أول استفسار للتحسين.*

## 3. حزمة التقنيات الموصى بها (Stack)

- **الإطار**: Next.js 14 (App Router)
- **مكتبة UI**: TailwindCSS + Shadcn/UI (تصميم بسيط وراقٍ)
- **إدارة الحالة**: Zustand (مع الوسيط `persist` لتحقيق تخزين الإعدادات الدائم)
- **قاعدة البيانات المحلية**: Dexie.js (لإدارة IndexedDB)
- **AI SDK**: Vercel AI SDK (معالجة النقل المتدفّق عبر الخطّاف `useChat`)

## 4. خطة العمل للخطوة التالية
سنسير على ثلاث خطوات:
1.  **بناء الهيكل (Scaffolding)**: تهيئة مشروع Next.js، وتهيئة Shadcn/UI و Zustand.
2.  **تنفيذ التفاعل الأساسي**: تنفيذ لوحة إعدادات الذكاء الاصطناعي (التخزين المحلي) وواجهة المحادثة الأساسية.
3.  **تطوير منطق التحسين**: تنفيذ مكوّن التفاعل "توليد-معاينة-اختيار" (Generative UI).
