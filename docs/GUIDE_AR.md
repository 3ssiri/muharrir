## نظرة عامة

التطبيق مبني على **Next.js 14 (App Router)** ويعمل **محليًا أولاً**: الإعدادات في `LocalStorage` (عبر Zustand) والمحادثات في `IndexedDB` (عبر Dexie). الواجهة تدعم **العربية والإنجليزية** مع اتجاه RTL كامل للعربية.

تمّت تهيئة المشروع لـ **التصدير الثابت** (`output: 'export'`) حتى يعمل داخل **Tauri v2** بلا خادم. ولأن التصدير الثابت لا يدعم مسارات الخادم (API routes) ولا الـ middleware، تُنفَّذ نداءات الذكاء الاصطناعي وتحليل الملفات **من جانب المتصفح مباشرةً**.

## التشغيل في وضع التطوير

```bash
git clone https://github.com/3ssiri/interactive-prompt-iterator.git
cd interactive-prompt-iterator
npm install
npm run dev
```

ثم افتح [http://localhost:3000](http://localhost:3000). سيُعاد توجيهك تلقائيًا إلى لغتك (`/ar` أو `/en`).

## إعداد الذكاء الاصطناعي

من أيقونة **الإعدادات (⚙️)** أدخل:

| الحقل | الوصف |
|---|---|
| **مفتاح API** | مفتاح OpenAI/Claude أو أي مزوّد متوافق مع OpenAI |
| **Base URL** | عنوان المزوّد، الافتراضي `https://api.openai.com/v1` |
| **النموذج** | النموذج المطلوب (مثل `gpt-4o`) |
| **نموذج التصحيح** | لتصحيح صيغة استدعاء الأدوات تلقائيًا (الافتراضي `grok-beta-fast`) |
| **موجّه النظام** | اختياري، لتخصيص سلوك المساعد |

> 💡 جرّب الوضع التجريبي بإدخال `demo` كمفتاح API لمعاينة البثّ دون مزوّد حقيقي.
> 💡 كل الإعدادات محلية ولا تُرفع لأي خادم. استخدم زرّي الاستيراد/التصدير لنقلها بين الأجهزة.

## البناء كتطبيق ويب (Static Export)

```bash
npm run build
```

يولّد هذا الأمر مجلد `out/` يحتوي ملفات HTML/JS الثابتة (بما فيها `/ar` و`/en`). يمكن استضافة محتوى `out/` على أي خادم ملفات ثابت.

---

## التحويل إلى تطبيق سطح مكتب (Tauri v2)

بعد تهيئة مجلد `src-tauri/` (راجع `CLAUDE.md` للخطوات التفصيلية):

```bash
# تشغيل نافذة Tauri في وضع التطوير
npm run tauri dev

# بناء حزمة التوزيع لنظامك
npm run tauri build
```

مخرجات البناء:
- **Windows**: `src-tauri/target/release/bundle/msi/`
- **macOS**: `src-tauri/target/release/bundle/dmg/`
- **Linux**: `src-tauri/target/release/bundle/appimage/`

> 📌 تأكّد أن `tauri.conf.json` يشير إلى `frontendDist: "../out"`.

## البنية client-side (بدائل مسارات الخادم)

بما أن `output: 'export'` يمنع مسارات الخادم، حُذف مجلد `src/app/api` واستُبدل بـ:

- **`src/lib/chat-client.ts`** — بديل عن `/api/chat`. يرسل الطلب مباشرةً إلى `{baseUrl}/chat/completions` ويُعيد بثًّا بنفس البروتوكول السابق:
  - `0:"نص"` المحتوى النصّي
  - `9:{...}` استدعاء أداة
  - `a:{...}` نتيجة أداة
  - `e:{...}` خطأ / حالة تصحيح

  ويحتفظ بالوضع التجريبي (`demo`)، والأدوات الثلاث (`ask_questions`، `suggest_enhancements`، `propose_prompt`)، ومنطق التحقّق/التصحيح ومعالجة الأخطاء (401/404/429/5xx).

- **`src/lib/file-parser-client.ts`** — بديل عن `/api/parse-file`. يحلّل PDF عبر `pdfjs-dist` وDOCX عبر `mammoth` داخل المتصفح، ويُعيد `{ text }`.

- **فحص الإصدار** في `version-badge.tsx` يستدعي GitHub API مباشرةً (client-side) بدلاً من المسار المحذوف `/api/version`.

> ⚠️ في متصفح الويب العادي قد يفشل النداء المباشر للمزوّد بسبب CORS، لكن داخل Tauri يعمل بشكل طبيعي.

## التدويل ودعم RTL

- إعداد اللغات في `src/i18n/config.ts` و`src/i18n/routing.ts`: `['ar', 'en']` واللغة الافتراضية `ar`، مع `localePrefix: 'as-needed'`.
- ملفات الترجمة في `src/i18n/locales/ar.json` و`en.json`.
- يُضبط اتجاه الصفحة في `[locale]/layout.tsx` عبر `dir` (RTL للعربية) ويُحمّل خط **Cairo** للعربية.
- المكوّنات تستخدم أصناف Tailwind **المنطقية** (`ps/pe`, `ms/me`, `start/end`, `text-start/end`) لتنعكس تلقائيًا حسب الاتجاه.

## حلّ المشاكل الشائعة

| المشكلة | السبب | الحل |
|---|---|---|
| فشل `output: 'export'` بسبب مسارات API | مسارات الخادم لا تعمل مع التصدير الثابت | تم نقل المنطق إلى `chat-client.ts` و`file-parser-client.ts` |
| خطأ next-intl عند البناء | نقص `generateStaticParams`/`setRequestLocale` | مُضافان في `[locale]/layout.tsx` |
| واجهة بيضاء داخل Tauri | `frontendDist` خاطئ | اضبطه على `"../out"` في `tauri.conf.json` |
| عامل PDF لا يعمل | مسار الـ worker | يُنسخ `pdf.worker.min.mjs` إلى `public/` عند البناء |
| فشل نداء المزوّد في المتصفح | قيود CORS | استخدم تطبيق Tauri، أو مزوّدًا يسمح بـ CORS |
```
